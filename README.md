# 哈基米投资记账（演示版）

一个**给自己用的投资记账工具**：把散在多个券商 App、支付宝、银行里的钱，收敛成一张资产负债表，每周花十分钟记一次，回答三个问题——

1. 我现在到底有多少钱？
2. 每一类资产占多少，有没有超过我自己定的上限？
3. 这周我有没有做计划外的交易？

纯静态：一个 `index.html` + 一个 `data.js`。无后端、无数据库、无登录、无构建步骤。双击能跑，扔到 GitHub Pages 能给别人看。

> **⚠️ 本仓库所有数字均为虚构。**
> 总资产、持仓、成本、股数、交割收益、历史快照全部由脚本生成，与任何真实账户无关。标的名称为真实上市公司，仅用于示意格式，不构成任何推荐。
>
> **本工具不是投资建议。** 它不预测涨跌、不推荐买卖，只做记账、勾稽和规则检查。

**在线预览：https://zhoujinq.github.io/hajimi-ledger-demo/**

## 它长什么样

打开页面，从上到下是：

1. **当前状态** —— 总资产 / 总负债 / 净资产 / 较上次变化，以及六类资产的占比条
2. **本周记账向导** —— 六张可折叠的卡片，按顺序抄数
3. **提交前预览** —— 用表内现有公式把你这周填的数算一遍，先看结果再提交
4. **确认记账** —— 生成一条记账记录

不是仪表盘，是一个**向导**。因为记账这件事最难的不是算，是「别忘了抄哪一格」。

## 30 秒跑起来

### 方式一：直接双击

双击 `index.html`。

> `file://` 协议下「实时行情」会被浏览器拦掉，页面会停在快照价。不影响记账和看数。

### 方式二：起个本地服务（推荐）

需要 Python 3（Windows 装的时候记得勾 “Add Python to PATH”）。

在这个文件夹里打开终端：

```bash
python -m http.server 8000
```

浏览器打开 `http://localhost:8000`。`Ctrl + C` 停止。

### 方式三：VS Code

装 **Live Server** 扩展 → 右键 `index.html` → *Open with Live Server*。

## 界面导览

顶部是六张折叠卡片，按 **0 → 6** 的顺序走一遍，就是一次完整记账。

| 步骤 | 卡片 | 你要做的事 |
|---|---|---|
| 0 | 我的持仓（港美股 + A股） | 填「本周新增交易」。填一笔买入，下面台账里的股数立刻变——**不用手工改持仓** |
| 1 | 腾达证券 | 一般不用动。港币现金按货基处理，页面会算一周的增长建议值 |
| 2 | 汇丰 App | **每周唯一必须手抄的地方**：港股/美股市值和现金，四个数 |
| 3 | 港美股交割收益 | 本周有卖出才需要填累计交割收益 |
| 4 | 支付宝 | 总资产、各类基金、黄金 |
| 5 | 网商银行 | 现金、本周存钱、零钱 |
| 6 | 广发证券 | 三只 ETF 的市值 = 现价 × 股数，**自动算，不用填** |

填完点「提交前预览」，页面会用表内公式把新总资产算出来给你看；确认无误再点「确认记账」。

### 几个刻意设计

**股数只有一个真相源。** 台账里不能手填股数，只能「填交易」。手改股数等于改基线，会标橙并在本地留痕——因为「记错了」和「买入了」在账上必须能分开。

**汇总是算出来的，不是填的。** 总资产、净资产、各类占比、现金水位，全部由单元格互推。你只需要保证抄进来的原始数字是对的，剩下的别管。

**实时校验常驻。** 页面底部会跑几条勾稽：台账市值 vs 券商账户市值、汇率闭合、现金水位。对不上就是红的——那说明股数错、漏记交易或抄错数，三种错一次抓出来。

## 数据是怎么组织的

`data.js` 里只有一个对象：

```js
const DATA = {
  SNAPSHOT:        { "B6": 872341, "D23": 81880, ... },   // 上一次记账后表里的值
  INPUT_DEFAULTS:  { "F5": 1.1765, "D23": 81880, ... },   // 输入框的默认值
  POSITIONS:       { items: [ ... ], trades: [ ... ] },   // 持仓台账
  HISTORY:         [ ... ],                                // 历史快照
  EVENTS:          [ ... ],                                // 每次记账的事件
  QUOTES:          { quotes: [ ... ] },                    // 行情缓存
  FILE_URL:        ""                                      // 关联的在线表格（本演示版为空）
};
```

- `SNAPSHOT` / `INPUT_DEFAULTS` 的键是**表格坐标**（`B6` 就是资产负债表第 6 行），因为整个页面就是围绕一张 60×28 的表格写的。
- `POSITIONS.items` 才是你平时会看的部分：每只标的的 `code / shares / cost / cur`。
- `cost` 和 `price` **一律用原币**（港股填港币、美股填美元），折人民币是页面按汇率算的。不要在数据里提前折算，否则汇率一变你的成本就跟着变。

## 改成你自己的数据

### 只想换持仓（最常见）

改 `POSITIONS.items`，每项保留字段名：

```js
{ "id":"NVDA", "ref":"C17", "code":"usNVDA", "name":"英伟达",
  "market":"us", "account":"hsbc", "kind":"stock",
  "shares":30, "cost":121.40, "cur":"USD" }
```

- `code` 决定能不能取实时价：港股 `hk` + 5 位、美股 `us` + 代码、A股 `sh/sz/bj` + 6 位。
- `ref` 是这张表里对应的单元格（`C10`~`C22` 是港美股持仓行），不确定就别改。
- 改完刷新，台账立刻生效；但「当前状态」的总资产来自 `SNAPSHOT`，需要你按新持仓改 `B6` 等单元格，或者用它自己的记账流程重新记一次。

### 想从零建一套自己的账

最省事的做法不是改这个演示数据，而是：

1. 把 `data.js` 里的 `SNAPSHOT` 当成模板，保留键名；
2. 按你自己的表格结构，把 `B6`（总资产）、`D23`（港股）、`D25`（美股）、`I24`~`I38`（A股与黄金）、`D32`（人民币现金）填成你的数；
3. 让页面自己算派生值——它有一套公式，会在预览区把结果算给你看。

如果你不想碰公式，也可以只用它的**台账部分**：把 `index.html` 里 `showView("dash")` 之后的分步卡片注释掉，只留第 0 步。

## 实时行情

页面用 `<script>` 标签请求腾讯公开行情接口：

```
https://qt.gtimg.cn/q=hk02513,usNVDA,sh688256,...
```

返回一段 JS 赋值（`v_hk02513="100~智谱~02513~334.00~...";`），页面按 `~` 切开取第 4 个字段当现价。

用 `<script>` 而不是 `fetch`，是因为这个接口没有开放跨域头，`fetch` 会被同源策略拦掉，而 `<script>` 不受限制。

**可用则用，不可用就退**：取到价就用实时价重算；取不到（断网、接口变更、`file://` 打开）就用 `data.js` 里的快照价，页面照常能用。

> 公开但非官方承诺的接口，随时可能变。个人自用没问题，别拿它做生产系统。

## 几个设计取舍

**记账和行情解耦。** 记账是「我有什么」，行情是「它现在值多少」。前者必须准，后者可以晚。所以行情挂了页面不报错，只是把数字退回上一次快照。

**股数是主键，市值是派生。** 只存股数，市值永远现算。价格涨跌不会污染持仓记录，也不会出现「上周改了市值、这周忘了改」。

**上限只是显示，不是门禁。** 目标区间只用来标红，不阻止任何操作。因为真正需要被拦住的往往不是「超了 10%」，而是「在情绪里下的单」——那件事拦不住，只能事后看见。

**校验比提醒有用。** 与其提醒你「记得对齐」，不如每次自动算一遍，对不上就红给你看。

## 脱敏说明

本仓库的数字由脚本生成，规则可复现：

| 项目 | 规则 | 本例 |
|---|---|---|
| 总资产 | 600,000 ~ 1,000,000 随机 | **872,341** |
| 港股个股 | < 10% | 8.0% |
| 美股个股 | < 10% | 8.8% |
| A股个股 | < 10% | 7.3% |
| 美股指数基金 | 20% ~ 30% | 26.0% |
| 黄金 | < 15% | 13.7% |
| 现金 | 剩余 | 36.2% |
| 每市场标的 | 5 只 | 港5 / 美5 / A5 |
| 股数 | 目标金额 ÷ 当日价 ÷ 每手股数 取整 | — |
| 成本价 | 当日价 ±8% 内随机 | — |

**为什么不拿真数据打码？**

因为打码很容易漏。真实记账项目里敏感的不只是总资产，还有每笔交易的日期与金额、券商账户余额、代持份额、在线表格 ID、甚至备注里的一句人名。任何一处漏掉都能被反推。所以这里不搬运任何真实记录，只保留格式、重造数字。

## 常见问题

**Q：打开后数字全是「—」或空白？**

`data.js` 没加载成功。F12 看 Console 有没有 404，检查两个文件是否在同一目录、文件名大小写是否一致。

**Q：六类占比加起来不是 100%？**

说明 `SNAPSHOT` 里的派生值（`E13`~`E18`）和输入值（`D23`/`D25`/`I24`…）不同步。这两个必须同时改。

**Q：实时行情一直不刷新？**

三种可能：`file://` 打开、接口被拦、代码前缀写错（`sh` 写成 `sz`）。前两种不影响记账。

**Q：为什么涨是红色、跌是绿色？**

A 股和港股的习惯是涨红跌绿，页面遵循这个。习惯美股配色的话，把 CSS 里 `.up` 和 `.down` 的颜色对调。

**Q：能不能自动从券商同步？**

不能。券商没有面向个人的开放接口，任何「同步」都得靠爬虫或截图识别，既不稳也不安全。这个项目的定位是**手动记账，但记得快**——每周十分钟，比接一个随时会坏的自动化可靠。
