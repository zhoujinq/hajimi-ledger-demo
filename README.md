# 哈基米投资记账（演示版）

一个**给自己用的投资记账与持仓台账**：把散在 5 个券商 App、支付宝、银行里的钱，收敛到一张表里，回答三个问题——

1. 我现在到底有多少钱？
2. 每一类资产占多少，超没超我自己定的上限？
3. 这周我有没有做计划外的交易？

页面是纯静态的（一个 `index.html` + 一个 `data.js`），不依赖后端、不需要数据库、不需要登录。双击就能跑，扔到 GitHub Pages 就能给别人看。

> **⚠️ 本仓库里的所有数字都是虚构的**，用脚本生成，与任何真实账户无关。生成规则见[《数据脱敏说明》](#数据脱敏说明)。标的名称为真实上市公司，仅用于示意格式，不构成任何推荐。
>
> **本工具不是投资建议**，不预测涨跌、不推荐买卖。它只做记账、勾稽和规则检查。

## 先看效果

直接打开：**https://zhoujinq.github.io/hajimi-ledger-demo/**

打开后你会看到：

- 顶部四张卡：总资产 / 净资产 / 现金 / 现金水位

## 它长什么样、能干什么

| 区块 | 作用 | 数据来源 |
|---|---|---|
| 四张 KPI 卡 | 总资产、净资产、现金、现金水位 | `data.js` |
| 资产配置 | 六类资产金额/占比/目标区间 | `positions` 汇总 + `cash` |
| 港股/美股/A股持仓 | 股数 × 现价 = 市值，算占比 | `positions` + 实时价 |
| 指数与黄金 | 纳指 ETF、黄金 ETF 的份额与市值 | `positions.usindex` / `positions.gold` |
| 自动校验 | 台账市值与券商账户市值是否对得上 | `checks`（演示版为静态文本） |

**为什么要有「股数」这一列**

因为市值会骗人，股数不会。市值 = 股数 × 现价，价格一变市值就变，你分不清是「我买了」还是「它涨了」。把股数单独列出来，再让「股数 = 期初基线 + 之后每一笔买卖」，才能回答「我这周到底动了没有」。

**为什么要有「占比」这一列**

因为你给自己定了上限（比如单只个股不超过总资产 10%）。上限是防「不知不觉重仓」的，而人对自己仓位的感知，在上涨时会系统性低估、下跌时会系统性高估。占比是唯一不会骗你的那个数。

## 数据是怎么组织的

`data.js` 只做一件事：往全局挂一个 `window.DEMO` 对象。

```js
window.DEMO = {
  as_of: "2026-11-21",          // 数据截止日
  currency: "CNY",              // 记账本位币
  fx: {                         // 汇率：1 单位外币 = 多少人民币
    cnyPerHkd: 1 / 1.175,
    cnyPerUsd: 6.673
  },
  total: 872341,                // 总资产（含现金）
  liabilities: 1840,            // 负债（花呗之类）
  cash: 313972,                 // 现金（人民币+港币+美元，已折人民币）
  buckets: [ ... ],             // 六类资产的显示顺序、目标区间、颜色
  positions: { hk: [...], us: [...], cn: [...], usindex: [...], gold: [...] },
  checks: [ ... ]               // 校验项的展示文本
};
```

### `buckets`：资产分类

```js
{ key: "hk", name: "港股个股", target: [0, 10], color: "#1a73e8" }
```

- `target` 是你给自己定的占比区间（百分数）。演示数据里：港股/美股/A股个股 ≤10%，美股指数 20–30%，黄金 ≤15%，现金「剩余」。
- 这个区间**只用于显示**，不会拦你交易。它的作用是让你一眼看到「我超了」。

### `positions`：持仓

每一只标的的字段：

| 字段 | 含义 | 例子 |
|---|---|---|
| `code` | 行情代码（决定能不能取实时价） | `hk02513` / `usNVDA` / `sh688256` |
| `symbol` | 显示用的代码 | `02513` |
| `name` | 显示名 | `智谱` |
| `shares` | 股数（可以是小数，美股常见） | `100` |
| `cost` | 成本价（**原币**，不是人民币） | `336.0` |
| `price` | 快照价（**原币**，取不到实时价时用它） | `334.0` |
| `cur` | 计价货币 | `HKD` / `USD` / `CNY` |

**关键：`cost` 和 `price` 一定是原币。** 港币股填港币，美股填美元，A股填人民币。折人民币是页面用 `fx` 算的，不要在数据里提前折算——否则汇率一变，你的成本就跟着变了，那是错的。

### 币种与汇率

页面按 `cur` 分三路折算：

```
港股：市值(CNY) = 股数 × 现价(HKD) × cnyPerHkd
美股：市值(CNY) = 股数 × 现价(USD) × cnyPerUsd
A股：市值(CNY) = 股数 × 现价(CNY)
```

`cnyPerHkd` 写的是「1 港币 = 多少人民币」，演示值 `1/1.175 ≈ 0.851`。你换成当天汇率即可。

## 改成你自己的数据（手把手）

假设你只有 3 只港股、2 只美股，其他都没有。按下面 6 步改，**只动 `data.js`，不要动 `index.html`**。

### 第 1 步：改总资产和现金

```js
total: 872341,     →  total: 250000,
cash:  313972,     →  cash:  80000,
```

`total` 必须等于「所有持仓市值折人民币之和 + cash」。不一致的话，配置表的占比加起来不会是 100%。

### 第 2 步：改汇率

```js
fx: { cnyPerHkd: 1 / 1.175, cnyPerUsd: 6.673 }
```

打开任意一个汇率网站，查「1 HKD 兑 CNY」和「1 USD 兑 CNY」，直接填数：

```js
fx: { cnyPerHkd: 0.9120, cnyPerUsd: 7.1050 }
```

### 第 3 步：改港股持仓

```js
hk: [
  { code:"hk02513", symbol:"02513", name:"智谱", shares:100, cost:336.0, price:334.0, cur:"HKD" },
  { code:"hk09988", symbol:"09988", name:"阿里巴巴-W", shares:200, cost:91.2, price:83.35, cur:"HKD" }
]
```

删掉不要的行，保留你要的。**注意逗号**：最后一行后面不要留逗号。

### 第 4 步：改美股和 A 股

同理。A 股的 `code` 规则是「交易所前缀 + 6 位代码」：

- 上海：`sh` + `600xxx` / `688xxx`（例：`sh688256`）
- 深圳：`sz` + `000xxx` / `300xxx`（例：`sz300308`）
- 北京：`bj` + `8xxxxx`

写错前缀会导致取不到行情，页面会回退到你的 `price`——不影响显示，只是不实时。

### 第 5 步：改分类目标

如果你不做黄金，就把黄金那行的 `target` 改成 `[0,0]`，或者直接从 `buckets` 里删掉那一行（同时把 `positions.gold` 清成 `[]`）。

### 第 6 步：刷新

本地服务的话直接刷新浏览器；GitHub Pages 的话 `git commit` + `git push`，等 1 分钟。

### 怎么验证改对了

打开页面，看资产配置表最下面：**六类占比加起来必须是 100.0%**。

如果不是 100%，只有两种可能：
1. `total` ≠ 持仓市值之和 + `cash`
2. 某只标的的 `cur` 填错了（比如美股填了 `CNY`，市值会差 6.6 倍）

## 实时行情是怎么接的

页面用 `<script>` 标签去请求腾讯公开行情接口：

```
https://qt.gtimg.cn/q=hk02513,hk09988,usNVDA,sh688256,...
```

返回的是一段 JS 赋值（`v_hk02513="100~智谱~02513~334.00~...";`），页面按 `~` 切开取第 4 个字段作为现价。之所以用 `<script>` 而不是 `fetch`，是因为这个接口没有开放跨域头，`fetch` 会被浏览器的同源策略拦掉，而 `<script>` 不受这个限制。

**设计上是「可用则用，不可用就退」**：

- 取到价 → 用实时价重算市值，右上角标签变「实时」
- 取不到（断网、接口变更、`file://` 打开）→ 用 `data.js` 里的 `price`，标签显示「快照」，页面照常可用

这样做的好处是：**行情挂了不影响你记账**。记账是主功能，行情是锦上添花。

> 提醒：这是公开但非官方承诺的接口，随时可能变。个人自用没问题，别拿它做生产系统。

## 三个设计原则

**1. 记账和行情解耦。** 记账是「我有什么」，行情是「它现在值多少」。前者必须准确，后者可以延迟。所以行情失败时页面不报错，只是把数字退回到上一次快照。

**2. 股数是主键，市值是派生。** 数据里只存 `shares`，市值永远现算。这样价格涨跌不会污染你的持仓记录，也不会出现「上周改了市值、这周忘了改」的错账。

**3. 上限是显示，不是门禁。** 目标区间只用来标红提示，不阻止任何操作。因为真正需要被阻止的，往往不是「超了 10%」，而是「在情绪里下的单」——那件事拦不住，只能事后看见。

## 数据脱敏说明

本仓库的 `data.js` 是**脚本生成的虚构数据**，规则如下（可复现）：

| 项目 | 规则 | 本例取值 |
|---|---|---|
| 总资产 | 在 600,000 ~ 1,000,000 之间随机取值 | **872,341** |
| 港股个股 | 占总资产 < 10% | 8.0% |
| 美股个股 | < 10% | 8.8% |
| A股个股 | < 10% | 7.3% |
| 美股指数基金 | 20% ~ 30% | 26.2% |
| 黄金 | < 15% | 13.7% |
| 现金 | 剩余 | 36.0% |
| 每个市场标的数 | 5 只 | 港股 5 / 美股 5 / A股 5 |
| 股数 | 按目标金额 ÷ 当日价 ÷ 每手股数，向下取整 | — |
| 成本价 | 在当日价 ±8% 内随机 | — |

**为什么不用真数据打个码了事？**

因为「打码」很容易漏。真实的记账项目里，敏感的不只是总资产，还有：每笔交易的日期与金额、券商账户的现金余额、代持人的份额、甚至文档 ID 和 API 地址。任何一处漏掉，都能被反推出全部。所以这里干脆**不搬运任何真实记录**，只保留格式，重造一套数字。

如果你要基于本项目记账，请把 `data.js` 放在一个**私有**仓库里，不要提交到公开仓库。

## 常见问题

**Q：打开后数字全是「—」，配置表是空的？**

八成是 `data.js` 加载失败。打开浏览器控制台（F12 → Console），看有没有红色的 404。常见原因：`data.js` 和 `index.html` 不在同一目录，或者文件名大小写不一致。

**Q：占比加起来不是 100%？**

见上文《怎么验证改对了》。

**Q：实时行情一直是「快照」？**

三种可能：① 用 `file://` 双击打开的；② 网络或接口被墙/变更；③ 代码前缀写错（`sh` 写成 `sz`）。前两种不影响使用，第三种改代码即可。

**Q：港股的涨跌颜色为什么是反的？**

不是反的。A 股和港股的习惯是**涨红跌绿**，本页面遵循这个习惯（`--red` 用于上涨）。如果你习惯美股的绿涨红跌，把 CSS 里 `.up` 和 `.down` 两个类的颜色对调即可。

**Q：能不能自动从券商同步持仓？**

不能，也不打算做。券商没有面向个人的开放接口，任何「同步」都得靠爬虫或截屏识别，既不稳定也不安全。这个项目的定位是**手动记账，但记得快**——每周花十分钟，比接一个随时会坏掉的自动化更可靠。

**Q：为什么没有「收益曲线」？**

因为历史净值需要长期记录才有意义。本项目的做法是每周记一次快照、写进一个 JSON 文件；累积三个月后再画图才有价值。演示版没有带这部分数据。
